## 1. 목표와 범위

### 배경
전략 A는 월 약 1.1건만 거래하고 표본 외 50건까지 1년 이상 걸린다. 사용자는 주 1~2건을 목표로 정하고, A의 방법을 작은 파동에 적용하는 안을 골랐다.

### 결정 사항 (사용자, 2026-11-04)
1. 목표 빈도는 주 1~2건(월 4~8건)이다.
2. 시간만 축소한다(1시간 파동 + 15분 돌파). 나머지 규칙은 A와 같다.
3. 조건 완화(Q·S를 후보 범위의 최저값으로 고정)는 횟수가 모자랄 때만 쓰는 예비안이며, 수익이 아니라 횟수만 보고 정한다.
4. 손익비 기준 1.5는 낮추지 않는다.
5. 떨어지면 그 단계에서 끝낸다. 재시도와 다른 변형은 없다.

### 범위
- 포함: `stratd/` 연구 코드, 횟수 점검, 워크포워드, 잠금, 홀드아웃 1회.
- 제외: 모의매매 실행기와 실거래 연결. 홀드아웃을 통과하면 별도 명세로 설계한다. 그때의 모의매매 합격선은 30건 + 원인 불명 불일치 0건 + 사용자 승인으로 미리 정해 둔다.
- 변경 금지: A의 지문 대상(`types.py`, `config.py`, `indicators.py`, `data/candles.py`, `waves/`, `strategy/`, `engine/`, `execution/`, `risk/`, 폴더에 새 파일 추가 포함), `paper/`, `live/`, `backtest/`, `holdout.lock`, `paper.yml`, `ci.yml`, `stratb/`, `paperb/`. 지금 돌아가는 A 모의매매와 SHADOW는 재시작하지 않는다.

### 연구 정직성에 관한 한계
- 2017~2023 구간은 A와 B 연구로 이미 여러 번 봤다.
- 2024-01-01 이후 BTC는 A의 홀드아웃으로 쓰였고 결과를 봤다. D는 A의 축소판이라 이 구간의 결과는 독립적인 증거가 아니다. **홀드아웃 통과는 "버릴 이유가 없다"는 뜻일 뿐이고, 확인은 모의매매에서 한다.**
- 사전 추정: 비용(왕복 거래 금액의 약 0.2%)이 R로 환산해 대략 2배가 된다. A의 기대값은 거래당 약 0.2R로 어림되므로 D가 비용을 넘지 못할 가능성이 작지 않다. A의 기본 설정 7년 62건을 단순히 4배 하면 월 약 3건이라 1차 합격선에 못 미칠 수도 있다. 둘 다 추정이다.

## 2. 전략 규칙

| 항목 | A | D |
|---|---|---|
| 파동 봉 | 4시간 | 1시간 |
| 돌파 확인 봉 | 1시간 | 15분 |
| 자산 | BTC | BTC (같은 Coinbase 15분봉 캐시) |

**봉 개수로 같게 두는 값(숫자를 바꾸지 않는다):** `K4` 그리드, `atr_len` 14, `M` 12, `choch_bars` 3, 스윙 조회 4, ATR 버퍼(이제 1시간 ATR 기준), 윅 클립 6(이제 15분 ATR 기준), `warmup_4h` 200(33일 → 8.3일), 시간 손절 12/60봉(48~240시간 → 12~60시간).

**A와 그대로 같은 값:** 네 가지 진입 자리(W3, W5, W5_REV, C_END), `r_gate` 1.5, TP1 50% 후 손절 본전 이동, 추적 손절, W5_REV 위험 절반, 보수적 위험 1%·최대 3배, 비용(`CostParams` 기본값).

**실제 시간과 돈 기준이라 줄이지 않는 값:** 시간당 펀딩, 금요일 휴장·블랙아웃 시각, 뉴욕 날짜 기준 손실 한도와 24시간 정지, 체결당 수수료와 슬리피지, 연율화 8760시간, 비교용 4시간 EMA.

## 3. 구조

```
src/ewbot/stratd/
  config.py      D의 고정값, 파동·돌파 봉 길이
  clock.py       봉 길이를 인자로 받는 거래 달력 (data/candles.py의 달력을 작게 복사)
  waves.py       WaveEngine 하위 클래스 (1시간 봉 경계로 on_close)
  broker.py      15분 처리와 펀딩 1/4 부과 (stratb/engine.py 방식)
  engine.py      engine/loop.py의 _Run 하위 클래스. 진행 곡선은 시간당 점으로 낸다
  data.py        15분봉 읽기, D의 2024 가드, holdout-d.lock 검증
  baselines.py   무작위 대조군(시간 손절과 시간 격자를 D에 맞춘 복사본), 매수 후 보유·EMA는 시간봉 프레임으로 import
  research.py    run_grid_d, 워크포워드
  count.py       횟수 점검 (5.1절)
  fingerprint.py D의 지문
  holdout.py     잠금과 1회 실행 (②를 통과한 뒤 작성)
holdout-d.lock   D의 고정 파라미터·코드·데이터 해시와 1회 실행 결과
CLI  ewbot stratd count | walkforward | holdout lock | holdout run
```

- 시간표를 속이는 방식(타임스탬프 ×4)은 금지한다. 펀딩이 4배로 붙고 금요일 판단과 손실 한도 날짜가 깨진다. 실제 시각 그대로 하위 클래스로 돌린다.
- 15분봉을 `TradingEngine.run`에 그대로 넣지 않는다. 시간봉 기본값의 `fill_gaps`는 15분봉을 받으면 `ValueError`를 낸다(시험으로 확인, 2026-11-04).
- 성과 곡선은 시간당 점으로 낸다. `metrics.py`가 시간당 수익을 가정한다.
- A의 `GRID`, `config_for`, `folds`, `pick_plateau`, `evaluate_folds`, `compute_metrics`, `evaluate_criteria`는 import한다.
- 정적 가드: `allow_holdout`, `include_holdout`, `unlock_2024`를 쓰지 않고 `check_before_holdout`, `_map_tasks`, `_init_worker`를 import하지 않는다. 2024 이후를 여는 키워드는 D만의 `unlock_holdout_d`이고 `stratd/holdout.py`에서만 쓴다. 새 워크플로는 만들지 않는다.

## 5. 검증 단계

각 단계에서 떨어지면 D는 영구히 끝난다. 단계마다 결과를 사용자에게 보고한 뒤 넘어간다.

### 5.1 ① 횟수 점검 (2017-01-01 ~ 2023-12-31, 84개월)
- 엔진으로 시뮬레이션해서 센다. 한 번에 한 포지션, 반대 전환, 쿨다운이 경로에 달려 있어서 신호 수만 세면 틀린다. 손실 한도는 워크포워드처럼 끈다.
- `count.py`의 작업자는 **횟수만 반환한다**(진입 시각 기준 연도별·자리별 건수). 수익, R, 승률, 자산, 청산 사유를 계산하거나 출력하지 않는다. `metrics`를 import하지 않고 테스트로 막는다.
- **1차:** 60개 조합(K4 4 × Q_MIN 5 × S_MIN 3)의 월평균 건수 중앙값 ≥ 4.0이면 그리드 그대로 ②로 간다.
- **예비:** 미달이면 Q_MIN 0.5, S_MIN 0.0으로 고정하고 K4 4개를 센다. 중앙값 ≥ 4.0이면 이 4개 조합을 그리드로 삼아 ②로 간다.
- **중단:** 그래도 미달이면 수익을 보지 않고 끝낸다.
- 합격선은 결과를 본 뒤 바꾸지 않는다.

### 5.2 ② 워크포워드 (2017-01-01 ~ 2023-12-31)
- A의 틀 그대로: 학습 24개월·확인 6개월·6개월씩 이동, 학습 창 12건 이상·유한한 Calmar, 이웃 평균 Calmar로 선택, 이어 붙인 표본 외 곡선, 마지막으로 무언가를 고른 구간의 조합.
- 예비 그리드(K4 4개)로 왔다면 이웃은 K4 축의 양옆만 본다. `pick_plateau`가 이 모양을 못 받으면 같은 규칙의 얇은 래퍼를 `research.py`에 둔다.
- 진행 조건(B·C와 같음): 이어 붙인 표본 외 수익 > 0, 최종 조합이 마지막 구간에서 뽑힘(fallback 아님). 하나라도 어기면 끝낸다.

### 5.3 ③ 잠금과 홀드아웃 1회
- `holdout-d.lock`은 2024 이후 봉을 읽기 전에 ②의 보고서에서만 만든다. 조합, 전체 설정, 그리드, D 지문, 의존 모듈 해시, 2024 이전 15분봉 해시, 보고서 해시, 시작일, `REPLAY_ANCHOR`, 무작위 횟수와 시드(횟수는 `holdout.lock`의 값과 같게), `last_bar_ts`, 다이제스트를 담는다. 작업 트리가 깨끗해야 하고 커밋한다.
- **사용자 승인 후 1회만** 실행한다. 시도를 실행 전에 기록하고 결과를 `first_run`에 기록해 바로 커밋한다.
- 구간: 2024-01-01 ~ `last_bar_ts`, `REPLAY_ANCHOR`부터 재계산, 손실 한도 켬(A와 같음).
- 합격 기준은 A의 `evaluate_criteria`다: 샤프와 Calmar가 **C 기준선(같은 시간대로 돌린 mode "C")·매수 후 보유·무작위 평균**을 모두 넘고, 최대 낙폭 ≤ 15%, 거래 ≥ 50건. HYBRID는 돌리지 않는다.

### 5.4 ④ 모의매매
③을 통과하면 별도 명세로 설계한다. 1절의 합격선을 쓴다.

## 6. 테스트

- **축소 동등성(핵심):** A의 시험용 1시간·4시간 경로를 시간만 4분의 1로 압축해 D에 넣으면, 펀딩 0, 금요일 구간 제외, 손실 한도 끔 조건에서 A와 같은 신호, 봉 위치, 가격이 나와야 한다.
- 펀딩이 시간당 금액 그대로인지, 금요일 휴장이 실제 시각에 있는지, 15분봉이 빠짐없이 처리되는지.
- 2024 가드: 잠금 전 수집 거부, 읽기 필터, 이름만 맞는 잠금 거부.
- 격리: `stratd/`가 금지된 키워드와 함수를 쓰지 않음, A 지문 `e0435223…` 불변, 전체 테스트 통과.
- `count.py`가 성과 모듈을 import하지 않고 출력에 성과 값이 없음.

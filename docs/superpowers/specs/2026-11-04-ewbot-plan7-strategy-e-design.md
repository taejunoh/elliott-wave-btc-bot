# ewbot Plan 7: 전략 E(일봉 채널 돌파 추세 추종) 연구 설계 명세

- 작성일: 2026-11-04
- 상태: 사용자 결정(2026-11-04)에 따라 작성한 사전 등록 명세. **전략 E의 어떤 결과도 보기 전에 작성했다.**
- 관련 명세: Plan 1(연구 프로토콜), Plan 6(전략 D, 횟수 점검 방식과 격리 방식)

## 1. 목표와 범위

### 배경
전략 A는 위험 대비 성적은 좋지만 수익이 작다(홀드아웃 +7.3%, 낙폭 2.9%). 빈도를 늘리려던 B, C, D는 끝났다. 사용자는 파동이 아닌 근거로, 낙폭을 더 받아들이는 대신 수익 크기를 노리는 전략을 시험하기로 했다.

### 결정 사항 (사용자, 2026-11-04)
1. 전략 A와 SHADOW는 계속 돌리고 E를 함께 연구한다.
2. 최대 낙폭 기준은 **−30%** 이다.
3. 방식은 추세 추종이다.
4. E 다음에 5분봉 파동 시험을 별도 명세로 한다. 이 명세의 범위가 아니고, E의 결과와 상관없이 사용자가 다시 확인한다.

### 범위
- 포함: `strate/` 연구 코드, 횟수 점검, 워크포워드, 잠금, 홀드아웃 1회.
- 제외: 모의매매 실행기와 실거래 연결. ③을 통과하면 별도 명세로 한다.
- 변경 금지: A의 지문 대상(`types.py`, `config.py`, `indicators.py`, `data/candles.py`, `waves/`, `strategy/`, `engine/`, `execution/`, `risk/`, 폴더에 새 파일 추가 포함), `paper/`, `live/`, `backtest/`, `holdout.lock`, `paper.yml`, `ci.yml`, `stratb/`, `paperb/`. 지금 돌아가는 A 모의매매와 SHADOW는 재시작하지 않는다.

### 연구 정직성에 관한 한계
- 2017~2023 구간은 이미 여러 번 봤다.
- 2024-01-01 이후 BTC는 A의 홀드아웃으로 쓰였고, 비슷한 계열인 EMA 비교 전략의 그 구간 성적(샤프 0.79)도 봤다. 그래서 **③ 통과는 "버릴 이유가 없다"는 뜻일 뿐이고, 확인은 모의매매에서 한다.**
- 예상되는 불리한 점: 2017~2023은 BTC가 크게 오른 구간이라 단순 보유를 넘기가 어렵다. 롱 펀딩비 연 10%가 오래 들고 가는 전략에 크게 작용한다.

## 2. 전략 규칙

| 항목 | 값 |
|---|---|
| 자산 | BTC-USD 현물 시세로 시뮬레이션, 비용은 BIP 기준(A와 같음) |
| 판단 봉 | UTC 일봉 (1시간봉 24개를 묶음, 00:00 UTC 마감) |
| 진입 | 포지션이 없을 때, 일봉 종가 > 직전 N일 최고가면 롱, 종가 < 직전 N일 최저가면 숏. 다음 1시간봉 시가에 체결 |
| 청산 | 롱은 일봉 종가 < 직전 N/2일 최저가, 숏은 일봉 종가 > 직전 N/2일 최고가. 다음 1시간봉 시가에 체결 |
| 초기 손절 | 체결가에서 2 × ATR(20일). 이후 옮기지 않는다. 1시간봉으로 확인한다 |
| 반대 전환 | 청산 신호와 같은 종가가 반대쪽 N일 돌파이면 청산과 같은 시가에 반대로 진입한다 |
| 후보 N | 20, 40, 55, 100 (N/2는 정수 내림: 10, 20, 27, 50) |
| 위험 | 거래당 자본의 2%, 최대 레버리지 3배, 시작 자본과 계약 크기는 A의 백테스트와 같음 |
| 비용 | `CostParams` 기본값(수수료 0.05%, 슬리피지 0.05%, 롱 펀딩 연 10%) |
| 금요일 휴장·블랙아웃 | A와 같음. 휴장 중 나온 신호는 다음 열리는 시가에 체결한다 |

직전 N일에는 신호가 나온 그 일봉을 넣지 않는다. 위험 2%, ATR 배수 2, 청산 N/2는 그리드에 넣지 않고 고정한다. 합성 봉(빠진 시간을 채운 봉)은 A처럼 `fill_gaps`로 만들고 일봉에 포함한다.

손실 한도: ②는 A의 워크포워드처럼 끈다. ③은 누적 낙폭 30%에서 멈추고(A의 15% 대신), 하루 손실 한도와 연속 손실 정지는 끈다. A의 3% 일일 한도는 거래당 위험 2%와 맞지 않아 정상 손절마다 걸리기 때문이다.

사용자 확인(2026-11-04, 횟수 점검 전): ATR은 A의 Wilder 방식(`atr_series`)으로 일봉에 쓰고 신호 봉까지 포함한다. 계약 수는 체결 순간 시가와 그 시점 자본으로 정한다. `clip_wicks`는 쓰지 않고 일봉 고가·저가는 원래 값이다.

## 3. 구조

```
src/ewbot/strate/
  config.py    고정값, 후보 N, 손실 한도
  rules.py     일봉 묶기, 채널, ATR, 신호 (순수 함수)
  engine.py    1시간봉 시뮬레이션과 시간당 진행 곡선
  data.py      1시간봉 읽기, E의 2024 가드, holdout-e.lock 검증
  count.py     횟수 점검 (수익 값 없음)
  research.py  워크포워드 (②)
  holdout.py   잠금과 1회 실행 (②를 통과한 뒤 작성)
holdout-e.lock
CLI  ewbot strate count | walkforward | holdout lock | holdout run
```

- 모듈은 A의 비용, 사이징, 달력, `compute_metrics`, `folds`, `buy_hold`를 import만 한다. 파동과 전략 코드는 쓰지 않는다.
- 정적 가드: `allow_holdout`, `include_holdout`, `unlock_2024`, `check_before_holdout`, `_map_tasks`, `_init_worker`를 쓰지 않는다. 2024 이후를 여는 키워드는 E만의 `unlock_holdout_e`이고 `strate/holdout.py`에서만 쓴다. 새 워크플로는 만들지 않는다.

## 4. 데이터

- 캐시 `data/cache/BTC-USD_1h.parquet`는 A의 파일이고 2024 이후 봉이 들어 있을 수 있다. E는 이 파일을 고치지 않고, 읽을 때 `ts < 2024-01-01 00:00 UTC`로 거른다. 잠금 전에는 2024 이후 봉을 메모리에 올리지 않는다(parquet 필터).
- 2017-01-01 이전 봉은 쓰지 않는다. 처음 N일은 채널이 없어 신호가 없다.
- 잠금 뒤 재계산 시작점은 2023-07-01 00:00 UTC다(N = 100과 ATR 20일 준비 기간).

## 5. 검증 단계

떨어지면 E는 영구히 끝난다. 단계마다 결과를 사용자에게 보고한 뒤 넘어간다.

### 5.1 ① 횟수 점검 (2017-01-01 ~ 2023-12-31, 84개월)
- 엔진으로 시뮬레이션해 체결된 진입을 진입 시각 기준으로 센다. 손실 한도는 끈다. 수익, R, 승률, 자산, 청산 사유를 계산하거나 출력하지 않는다.
- 후보 4개의 월평균 건수 중앙값 ≥ **1.0** (건수 중앙값 ≥ 84)이면 ②로 간다. 미달이면 끝낸다.

### 5.2 ② 워크포워드 (2017-01-01 ~ 2023-12-31)
- A의 `folds()`: 학습 24개월, 확인 6개월, 6개월씩 이동, 첫 확인 구간 2019-01-01. 학습 창에서 **6건 이상**이고 Calmar가 유한한 후보만 고른다(A의 12건은 N = 100에서 충족하기 어려워 절반으로 정한다). 선택 점수는 N 축 양옆과 자신의 평균 Calmar다. 끝의 후보는 있는 이웃만 평균한다. 이어 붙인 표본 외 곡선으로 판정하고, 최종 후보는 마지막으로 무언가를 고른 구간의 후보다.
- 진행 조건 (모두 충족): 표본 외 수익 > 0, 최대 낙폭 ≤ 30%, 샤프와 Calmar가 같은 구간의 매수 후 보유(`buy_hold`, 같은 비용)보다 높음, 최종 후보가 마지막 구간에서 뽑힘.

### 5.3 ③ 잠금과 홀드아웃 1회
- `holdout-e.lock`은 2024 이후 봉을 읽기 전에 ②의 보고서에서만 만든다. 후보, 설정, E 코드 해시, 의존 모듈 해시, 2024 이전 봉 해시, 보고서 해시, 시작일, 재계산 시작점, `last_bar_ts`, 다이제스트를 담는다. 작업 트리가 깨끗해야 하고 커밋한다.
- **사용자 승인 후 1회만** 실행한다. 시도를 실행 전에 기록하고 결과를 `first_run`에 기록해 바로 커밋한다.
- 구간: 2024-01-01 ~ `last_bar_ts`. 합격 기준 (모두 충족): 수익 > 0, 최대 낙폭 ≤ 30%, 샤프와 Calmar가 매수 후 보유보다 높음, 비용 1.5배에서 수익 > 0. 거래 수 기준은 두지 않고 기록만 한다.

### 5.4 ④ 모의매매
③을 통과하면 별도 명세로 설계한다. 합격선은 ③의 건수와 합쳐 표본 외 50건 + 원인 불명 불일치 0건 + 사용자 승인으로 미리 정해 둔다.

## 6. 테스트

- 채널: 신호 봉이 자기 채널에 들어가지 않음(미래 정보 차단), 손으로 계산한 경로의 신호·체결.
- 손절: 초기 손절 고정, 간격을 뛰어넘는 시가 처리, 한 봉에서 손절과 신호가 겹칠 때 손절 우선.
- 비용: 펀딩이 시간당 금액으로 붙음, 숏은 A와 같은 처리.
- 일봉 묶기: 00:00 UTC 경계, 합성 봉 포함, 일봉 미완성 시 신호 없음.
- 2024 가드: 2024 이후 봉이 든 parquet에서 읽어도 거름, 잠금 전 키워드 거부, 이름만 맞는 잠금 거부.
- 격리: 금지 키워드 없음, A 지문 `e0435223…` 불변, 전체 테스트 통과.
- `count.py`가 성과 모듈을 부르지 않고 출력에 성과 값이 없음. 캐시가 구간을 덮지 않거나 빠진 시간이 많으면 거부.

## 8. 종료 기록 (2026-11-04)

**전략 E는 ① 횟수 점검에서 끝났다. 수익은 계산하지도 보지도 않았다.**

- 실행: `uv run ewbot strate count`, 2026-11-04 18:44 UTC, 커밋 `1ef956f`, 2017-01-01 ~ 2023-12-31(84개월). 1시간봉 61,301개, 빠진 시간 43시간.
- 건수: N = 20은 65건(월 0.77), N = 40은 39건(0.46), N = 55는 34건(0.40), N = 100은 22건(0.26).
- 중앙값 36.5건, 월 0.435건 < 합격선 84건(월 1.0건). 판정: **STOP.** 가장 많은 후보도 합격선에 못 미쳤다. 합격선은 결과를 본 뒤 바꾸지 않았다.
- 설계 때의 "월 1~3건"은 근거 없는 추정이었고 실제보다 많았다. 횟수 합격선은 표본 외 50건을 모을 수 있는지를 보는 것이고, 이 방식의 수익성을 판단한 것은 아니다.
- 워크포워드, `holdout-e.lock`, 2024 이후 데이터는 E를 위해 쓰지 않았다. 후속 변형은 없다. 전략 A, 모의매매, SHADOW는 바뀌지 않았다.
- E의 코드는 이 기록이 가리키는 브랜치 `docs/strategy-e`의 커밋 `1ef956f`에 남긴다.

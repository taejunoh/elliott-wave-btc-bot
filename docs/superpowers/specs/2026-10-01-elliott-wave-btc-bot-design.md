# Elliott Wave BTC 자동매매 봇 — 설계 명세

- 작성일: 2026-10-01
- 상태: 사용자 승인됨 (구현 계획 작성 전)

## 1. 목표와 범위

### 목표
- 4h 봉으로 Elliott Wave 구조를 인식하고 1h 봉에서 진입 타이밍을 잡아 BTC를 롱·숏 양방향으로 자동매매하는 봇.
- 백테스트, 모의매매(paper), 실거래(live)를 **같은 코드 경로**로 실행한다.
- "Elliott 카운팅이 실제로 가치를 더하는가"를 데이터로 판정할 수 있게 비교 기준선과 검증 절차를 내장한다.

### 비목표 (v1)
- 대각삼각형(leading/ending diagonal), 삼각수렴(triangle), 복합 조정(WXY) 인식
- 다중 degree 동시 카운팅
- 머신러닝 기반 탐지
- 다중 종목, 동시 다중 포지션
- 클라우드 배포 자동화 (Docker 이미지까지만 제공)

### 사용자 제약
- 사용자는 뉴욕 거주자다. Binance, Bybit, OKX, Kraken, Upbit는 쓸 수 없다.
- 1순위 시장은 **Coinbase Financial Markets 선물**이다. 24/7 nano BTC 무기한형 선물(0.01 BTC 단위)을 Advanced Trade API로 거래한다.
- 미확정 사항: 뉴욕 거주자가 Coinbase 선물을 쓸 수 있는지는 사용자가 계정에서 확인해야 한다. 불가하면 `IBKRBroker`(CME 마이크로 BTC 선물) 어댑터를 추가한다.
- 실거래의 API 키 입력과 실행은 사용자가 직접 한다. 개발 중 기본 모드는 `paper`다.

|---|---|---|---|
| `backtest` | Replay | PaperBroker | — |

### 이벤트 순서 (1h 봉 마감마다)
1. 1h 봉을 확정하고 이상치를 검사한다.
2. 이 봉으로 4h 봉이 닫히면 ZigZag(4h)를 갱신하고, count 열거·점수 계산·hysteresis를 수행한다.
3. 닫힌 1h 봉으로 `E_live`를 갱신하고, 무효화가를 넘은 count를 제거한다. done 여부와 `S_rev`를 다시 계산한다.
4. 보유 포지션을 관리한다: TP, 추적 손절, 시간 손절, lineage 소멸.
5. 진입 조건을 평가한다. 신호가 나면 **다음 1h 봉 시가에 시장가**로 진입한다.
6. 결정 스냅샷(top-k count, q, S_rev, 신호, 사유)을 SQLite에 저장한다.

4h 봉은 1h 봉을 집계해 만든다. 백테스트와 실시간이 같은 방식을 쓰도록 하기 위해서다.

## 4. 파동 인식 엔진

### 4.1 ZigZag (4h 구조용·1h 트리거용 공통 코드)
- 임계값은 `thr_t = K4 × ATR14_4h(t)`, 기본 K4 = 3.0이다. 1h용은 `K1 = 2.0 × ATR14_1h`다. ATR은 t까지의 봉만으로 계산한다.
- 극값 가격은 high/low(꼬리)로 기록한다. 무효화가와 손절가가 실제 거래된 가격이어야 하기 때문이다.
- 확정은 **종가 기준**이다. 극값에서 `thr` 이상 되돌린 close가 나와야 pivot이 확정된다.
- 이상 꼬리 정제: 꼬리가 6 × ATR1h를 넘으면 그 길이로 잘라 쓰고 로그를 남긴다.
- `Pivot(i, sub_ts, price, kind, confirmed_at)`은 불변이고 append-only다. `confirmed_at`은 확정된 4h 봉 index다.
- 진행 중인 leg는 잠정 극값 `E`(4h 기준)와 `E_live`(이후 닫힌 1h 봉까지 반영)로 표현한다.
- 같은 4h 봉 안에서 극값과 반전이 함께 일어나면, 극값이 생긴 1h 봉의 close와 그 이후 1h 봉들만으로 다음 leg의 초기 E를 잡는다.
- warmup은 4h 봉 200개다.

### 4.2 count 열거
- 후보 점은 최근 확정 pivot M = 12개와 가상 점 E다.
- count는 (pattern ∈ {IMP, ABC}, 방향 d ∈ {+1, −1}, phase)로 정의한다.
  - IMP의 phase: W2(3점), W3(4점), W4(5점), W5(6점)
  - ABC의 phase: B(3점), C(4점)
  - 점이 2개뿐인 W1, A phase는 비율 근거가 없으므로 제외한다.
- **패리티**: E의 kind는 진행 leg의 방향으로 정해진다. 예: bull W2/W4는 leg가 하락 중일 때만 가능하다.
- **pivot 건너뛰기 허용**: 라벨 점은 pivot의 부분수열로 고른다. 대신 extreme constraint를 건다. 라벨된 high는 양옆 라벨 점 사이의 모든 pivot high 이상이어야 하고, low는 그 반대다. 시작점 S는 [S, L₁] 구간의 극값이어야 한다.
- 탐색은 E에서 뒤로 DFS하며 hard rule을 점진적으로 검사해 가지를 친다. 최악의 경우에도 4h 봉 하나당 1만 노드 미만이다.
- 중복 제거: (pattern, d, phase, 마지막 확정 라벨 점 idx)가 같은 그룹에서는 q가 최대인 것 하나만 남긴다.

### 4.3 hard rule (bull 기준, bear는 가격 비교에 d를 곱한다)

| ID | 규칙 | 진행 중일 때의 무효화가 |
|---|---|---|
| H1 | P2 > S | E_live > S |
| H2 | P3 > P1 | W3 진행 중: price > P2 |
| H3 | W3가 \|W1\|, \|W3\|, \|W5\| 중 최단이 아님 | \|W3\| < \|W1\|이면 W5 상한 = P4 + \|W3\| |
| H4 | P4 > P1 (diagonal 미지원) | E_live > P1 |
| H5 | W5 진행 중 | E_live > P4 |
| A1 | \|B\|/\|A\| ≤ 1.382 | B 상한 |
| A2 | \|C\| ≤ 2.618\|A\| | C 상한 |

### 4.4 점수 계산
유사도 함수는 log 공간에서 계산하고 σ = 0.12다.
```
f_pt(x;{τ})   = max_τ exp(-ln²(x/τ)/(2σ²))
f_zone(x;a,b) = 1 if a≤x≤b else exp(-ln²(x/가까운경계)/(2σ²))
f_ip(x;hi)    = 1 if x≤hi else exp(-ln²(x/hi)/(2σ²))   # 진행 중 파동은 overshoot만 감점
```

| ID | 양 | 목표 | 가중치 w | 진행 중 hi (가중치 ×0.5) |
|---|---|---|---|---|
| g_start | IMP: 0.5·[S가 직전 4개 pivot low 중 최저] + 0.5·[P1이 S 직전 pivot high를 돌파]. ABC: [X가 직전 4개 pivot 중 극값] | — | 1.0 | — |
| g_r2 | \|W2\|/\|W1\| | zone [0.5, 0.618] | 1.0 | 0.786 |
| g_w3 | \|W3\|/\|W1\| | {1.618, 2.618} | 1.5 | 2.618 |
| g_r4 | \|W4\|/\|W3\| | zone [0.236, 0.382] | 1.0 | 0.5 |
| g_alt | min(1, \|r2 − r4\|/0.2) | — | 0.5 | W4 완료 시에만 |
| g_w5 | max(f_pt(W5/W1; {0.618, 1}), f_pt(W5/(S→P3); {0.618})) | — | 1.0 | 1.618 (W5/W1) |
| g_rB | \|B\|/\|A\| | zone [0.382, 0.618] ∪ [0.9, 1.236] | 1.0 | 1.382 |
| g_C | \|C\|/\|A\| | {1.0, 1.618} | 1.5 | 1.618 |

- 파동 길이는 산술 가격 차로 잰다. 시간 비율은 v1에서 쓰지 않는다.
- 적합도: `q = (Σ wⱼsⱼ + w0·0.5) / (Σ wⱼ + w0)`, w0 = 1. 근거가 적은 count는 0.5 쪽으로 수축된다.
- hysteresis
  - 직전 top count와 같은 lineage이면 `q' = q + h`, h = 0.05.
  - lineage는 (pattern, d, S_idx)가 같고, 확정 라벨 점이 이전 count의 prefix 확장인 경우다.
- 확률: `pᵢ = softmax(q'ᵢ / T)`, T = 0.05.
- 반전 합의 `S_rev = Σ_done p − Σ_notdone p`
  - `done_i = x_i ≥ zone_lo(phase)`
  - zone_lo: W2 0.382 / W3 1.0 / W4 0.236 / W5 0.618 + E가 P3 너머 / B 0.382 / C 0.786 + E가 A_end 너머
  - p는 4h 마감 시점에 고정하고, done 여부는 1h마다 E_live로 다시 계산한다.
- 동률 처리 순서: q 내림차순 → 점 수 내림차순 → S_idx 내림차순 → pivot idx 사전순
- top-k = 5는 로그와 대시보드용으로 보관한다. S_rev는 모든 그룹으로 계산한다.

## 5. 매매 셋업 (bull 기준, bear는 대칭)

### 5.1 셋업 표
| # | top count phase | 진입 구간 (E_live) | 방향 | 손절 | TP1 (50%) | TP2 (50%) | 시간 손절 기준 leg | 리스크 배수 |
|---|---|---|---|---|---|---|---|---|
| ① W3 | IMP+ W2 | r2 ∈ [0.382, 0.786] | L | S − 0.25ATR | E + 1.0·\|W1\| | E + 1.618·\|W1\| | W1 | 1.0 |
| ② W5 | IMP+ W4 | r4 ∈ [0.236, 0.5], E > P1 | L | P1 − 0.25ATR | P3 | min(H3 상한, max(E + \|W1\|, E + 0.618·(P3 − S))) | W1 | 1.0 |
| ③ 역추세 | IMP+ W5 | W5 ≥ 0.618·\|W1\|, E > P3, H3 상한 이내 | S | min(H3 상한, E_live + 0.5ATR) | E − 0.382·(E − S) | P4 | W5 | 0.5 |
| ④ C 종료 | ABC (A 하락) C | C/A ∈ [0.786, 1.786], E < A_end, (X − E)/(X − 직전 스윙 저점) ≤ 0.786 | L | E_live − 0.5ATR | E + 0.618·(X − E) | X | A | 1.0 |

- ATR은 4h ATR14다.
- ①과 ②의 손절은 count의 무효화가다. ③과 ④는 무효화가가 너무 멀어서 구조적 손절을 쓰고, count 무효화는 따로 감시한다.
- 직전 스윙 저점은 X 이전 lookback 구간의 최저 확정 low다.
- 셋업 on/off는 설정 파일에서 정하며 튜닝 대상이 아니다.

### 5.2 1h 트리거 (CHoCH)
- 기준선 H1은 진행 leg 안에서 E_live가 나온 1h 봉보다 **앞서** 확정된 마지막 1h pivot high다(1h ZigZag, K1 기준).
- 그런 pivot이 없으면(V자 반전) E 봉 직전 1h 봉 6개의 최고가를 쓴다.
- 트리거 조건: `close_t > H1` 그리고 `close_{t−1} ≤ H1`. bear는 대칭이다.

### 5.3 진입 조건 (모두 충족)
- flat 상태이고 서킷브레이커가 꺼져 있다.
- top count의 셋업이 활성화되어 있고, E_live가 진입 구간 안에 있다.
- `top.q ≥ Q_MIN`(기본 0.6), `S_rev ≥ S_MIN`(기본 0.25)
- 해당 instance (lineage, phase)가 cooldown 중이 아니다.
- 1h CHoCH 트리거가 발생했다.
- `blended_R = 0.5·R_TP1 + 0.5·R_TP2 ≥ 1.5`. R은 진입가 대비 (목표가 − 진입가)/(진입가 − 손절가)로 계산하고, 진입가는 트리거 봉 종가로 추정한다.
- 진입은 **다음 1h 봉 시가에 시장가**로 한다. 슬리피지와 테이커 수수료가 적용된다.
- 목표가는 진입 시점의 E로 고정하고 이후 바꾸지 않는다.

### 5.4 포지션 관리
- TP1이 체결되면 손절을 진입가(본전)로 옮긴다.
- 추적 손절: 진행 방향으로 새 4h pivot이 확정될 때마다 `stop = max(stop, pivot − 0.25ATR)`로 올린다. 다음 1h 봉부터 적용한다.
- 시간 손절: `clip(1.5 × 기준 leg의 4h 봉 수, 12, 60)`개 4h 봉 안에 TP1이 나오지 않으면 시장가로 청산한다. TP1 이후에는 해제한다.
- lineage 소멸: 진입 근거 count의 lineage가 새 확정 pivot 때문에 hard rule을 어기면 다음 1h 봉 시가에 청산한다.
- top count가 바뀌는 것만으로는 청산하지 않는다. 반대 방향 신호가 모든 진입 조건을 통과하면 포지션을 뒤집는다.
- cooldown: 손절로 끝난 instance (lineage, phase)는 phase가 바뀔 때까지 재진입하지 않는다.

### 5.5 기준선 C (피보나치 스윙)
- 같은 4h pivot을 쓴다.
- 추세 판정: 마지막 두 확정 high·low가 HH·HL이면 상승, LH·LL이면 하락, 그 외에는 관망이다.
- 상승 추세에서 진행 leg가 하락 중일 때: H = 마지막 확정 high, L = 그 직전 확정 low라 하고, `r = (H − E)/(H − L) ∈ [0.382, 0.786]`, `E > L`, 1h CHoCH, R 게이트를 모두 통과하면 롱 진입한다.
- 손절 = L − 0.25ATR, TP1 = H, TP2 = E + (H − L). 관리 규칙은 5.4와 같다.

### 5.6 하이브리드
1h마다 A의 상태를 분류한다.
- **CONFIDENT**: `top.q ≥ Q_MIN`이고 `S_rev ≥ S_MIN`. A 신호만 쓴다.
- **CONTRARY**: `S_rev ≤ −S_MIN`. C 신호도 막는다.
- **UNCERTAIN**: 나머지. C 신호를 허용한다.

### 5.7 무작위 진입 대조군 (백테스트 전용)
- A가 실제로 낸 신호 수와 같은 빈도로 무작위 시점과 방향에 진입한다.
- 손절 거리, TP 배수, 관리 규칙은 A가 실제로 낸 거래의 분포에서 뽑는다.
- 시드를 고정하고 100회 반복해서 분포를 비교한다.

## 6. 리스크 관리

### 6.1 프로파일
| 프로파일 | 거래당 리스크 | 레버리지 상한 |
|---|---|---|
| conservative (기본) | 1% | 3x |
| aggressive | 3% | 10x |

### 6.2 사이징
```
리스크 금액 = 평가자산 × 리스크% × 셋업 리스크 배수
손절 거리   = |진입가 − 손절가| + 예상 슬리피지
수량        = 리스크 금액 / 손절 거리
→ 명목가 ≤ 평가자산 × 레버리지 상한으로 자름 (손절가는 넓히지 않음)
→ 0.01 BTC 단위로 내림. 1계약 미만이면 진입하지 않음
→ 추정 청산가가 손절가보다 진입가에 가까우면 진입 거부
```

### 6.3 서킷브레이커 (프로파일 공통)
| 조건 | 동작 |
|---|---|
| 일일 손실 -3% (뉴욕 시간 00:00 리셋) | 당일 신규 진입 중지, 기존 포지션 유지 |
| 최고점 대비 누적 손실 -15% | 전량 청산, 봇 정지. Telegram `/resume`으로만 재개 |
| 연속 5패 | 24시간 신규 진입 중지 |
| 동시 포지션 | 최대 1개 |

## 7. 주문 실행과 장애 처리

### 7.1 주문 흐름 (live)
1. 다음 1h 봉 시가 직후에 시장가로 진입한다. 주문마다 고유한 `client_order_id`를 붙여 중복 주문을 막는다.
2. 체결 즉시 **거래소에 stop-market 손절 주문**과 TP1·TP2 지정가 reduce-only 주문을 건다.
3. 손절 주문이 실패하면 포지션을 즉시 시장가로 청산하고 알린다. 보호되지 않은 포지션은 허용하지 않는다.
4. 손절을 옮길 때(본전, 추적)는 새 손절 주문이 접수된 것을 확인한 뒤 기존 주문을 취소한다.

### 7.2 장애 대응
| 상황 | 대응 |
|---|---|
| 웹소켓 끊김 | 지수 백오프로 재연결하고 REST로 누락 캔들을 보충한 뒤 판단을 재개한다. 5분 넘게 미복구면 Telegram 경고 |
| 봇 재시작 | 거래소의 포지션·미체결 주문과 SQLite를 대조한다. 어긋나면 거래소 기준으로 맞추고, 손절 주문이 없으면 다시 건 뒤 알린다 |
| API 오류·속도 제한 | 재시도 3회(지수 백오프), 실패하면 알림 |
| 캔들 이상치 (0원, 비정상 급등락) | 해당 봉 판단을 건너뛰고 기록한다 |
| 펀딩비 | backtest·paper는 비용 모델로 반영하고, live는 실제 정산액을 기록한다 |

- Coinbase API 키는 거래 권한만 주고 출금 권한은 주지 않도록 문서에 안내한다.
- Telegram 명령은 설정에 등록된 chat_id에서 온 것만 처리한다.

## 9. 백테스트와 검증

### 9.1 데이터
- Coinbase BTC-USD 현물 1h 봉, 2017-01부터 현재까지. Parquet으로 캐시한다.
- 결측과 중복 봉을 검사하고 리포트를 남긴다.
- 신호는 현물로 계산하고 비용은 선물 기준으로 모델링한다.

### 9.2 체결 시뮬레이션 (PaperBroker)
- 시장가 진입: 다음 봉 시가 ± 슬리피지
- 손절: 손절가 ± 슬리피지. 시가가 손절가를 넘어 갭으로 열리면 시가에 체결한다.
- 지정가 TP: 진입 이후 어느 봉이든 그 봉의 범위가 TP가를 **초과해서 지나가야** 체결된 것으로 본다. 고가나 저가가 TP가와 정확히 같으면 미체결이다.
- 한 봉 안에서 손절과 TP가 모두 닿으면 손절이 먼저 체결된 것으로 본다.
- 비용 기본값(설정 가능)
  - 수수료는 구현 시점의 Coinbase 선물 수수료표 값을 쓴다.
  - 슬리피지 0.05%
  - 펀딩은 연 10% 상당을 롱이 부담하고 숏이 받는 것으로 가정한다.

### 9.3 워크포워드와 홀드아웃
```
2017-01 ─────────────── 2023-12 │ 2024-01 ──── 2026-09
   워크포워드 (튜닝 허용)          │   홀드아웃 (1회만)
```
- 튜닝 파라미터는 3개, 총 60개 조합이다.
  - K4 ∈ {2.0, 2.5, 3.0, 4.0}
  - Q_MIN ∈ {0.5, 0.55, 0.6, 0.65, 0.7}
  - S_MIN ∈ {0.0, 0.25, 0.5}
- 학습 24개월, 검증 6개월, 6개월씩 이동한다. 검증 구간은 2019H1부터 2023H2까지 10개다.
- 학습 목적함수는 Calmar다. 거래가 30건 미만인 조합은 제외한다.
- 단일 최고값 대신 **인접 격자 평균이 최고인 조합(plateau)**을 고른다.
- 홀드아웃은 마지막 학습 창에서 고른 파라미터로 한 번만 실행한다. 결과를 본 뒤 파라미터를 고치지 않는다.

### 9.4 비교 대상 (동일 비용 모델)
1. A: Elliott, 셋업별 결과 포함
2. C: 피보나치 스윙 기준선
3. A+C 하이브리드
4. 매수 후 보유
5. 50/200 EMA 교차 추세추종
6. 무작위 진입 대조군

### 9.5 지표와 리포트
- 지표: 순수익률, CAGR, 최대 낙폭, 샤프, 소르티노, Calmar, 승률, 평균 손익비, 거래 수, 노출 비율. 셋업별·롱숏별·연도별로 나누고, 부트스트랩 신뢰구간을 붙인다.
- q 구간별 적중률로 reliability 곡선을 그려 q가 실제로 의미 있는지 확인한다.
- HTML 리포트: 자산 곡선, 낙폭, 거래 목록, 비교표. 거래를 클릭하면 그 시점의 결정 스냅샷 차트가 나온다.

### 9.6 실거래 전환 기준 (모두 충족)
1. 홀드아웃에서 A 또는 하이브리드가 C, 매수 후 보유, 무작위 대조군보다 위험 대비 수익(샤프와 Calmar)이 높다.
2. 홀드아웃 최대 낙폭이 15% 이내다(conservative 기준).
3. 홀드아웃 거래가 50건 이상이다.
4. paper 모드를 최소 4주 운영했고, 그 기간의 신호와 체결이 같은 기간 백테스트와 일치한다(결정 스냅샷 비교).

## 12. 알려진 한계와 리스크
- **Elliott의 다의성**: q는 보정된 확률이 아니다. reliability 곡선과 무작위 대조군으로 검증해야 한다.
- **단일 degree**: 3파 연장(9파)과 2파 내부의 expanded flat은 오라벨될 수 있다.
- **진행 leg에서 조기 진입**: 확정을 기다리는 방식보다 빠르지만 거짓 진입이 늘어난다. 손실은 무효화가 손절로 제한된다.
- **diagonal 미지원**: 고점의 ending diagonal에서 셋업 ③을 놓친다.
- **산술 Fib**: 50% 이상의 큰 파동에서는 log 척도와 차이가 생긴다.
- **표본 크기**: 셋업당 연 수십 건이라 통계적 검정력이 낮다.
- **연구자 자유도**: 고정 가중치는 BTC 역사를 본 뒤에 정한 것이다. 홀드아웃은 1회만 쓴다.
- **현물 신호와 선물 체결의 괴리**: basis, 펀딩, 점검 창 때문에 손절 체결가가 다를 수 있다.
- **셋업 ②**: 손절이 멀어서 레버리지 상한에 걸려 수량이 줄 수 있다.
- **규제**: 뉴욕 거주자의 Coinbase 선물 이용 가능 여부가 미확인이다(1절).
